# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Skill Management

Skills from `coreyhaines31/marketingskills` are managed via the `skills` CLI:

```bash
# Install all skills from a repo
npx skills add coreyhaines31/marketingskills --yes

# Update installed skills
npx skills update --yes

# List installed skills
npx skills list
```

Installed skills are tracked in `skills-lock.json` (analogous to a package lock file). Do not edit this file manually.

## Architecture

This repository uses the [skills](https://skills.sh) framework, which lets AI agents load specialized behavior from markdown files.

### Skills (`/.agents/skills/`)

Each skill is a directory containing:
- **`SKILL.md`** — the skill definition, with YAML frontmatter (`name`, `description`, `metadata.version`) and markdown instructions for the agent
- **`references/`** — supporting docs the agent reads when running the skill (e.g., templates, benchmarks, platform specs)
- **`evals/evals.json`** — test cases with `prompt`, `expected_output`, and `assertions` arrays for validating skill behavior

The `description` frontmatter field is critical — it tells the agent when to automatically activate the skill. It should be comprehensive enough to cover all natural-language phrasings a user might use.

### Context Document (`/.agents/product-marketing-context.md`)

This file doesn't exist yet but is the foundational artifact all skills depend on. Before running most marketing skills, the agent should check if it exists and read it. Create it by running the `product-marketing-context` skill first — it interviews the user about their product, audience, positioning, and brand voice, then writes the file. All other skills reference it to avoid repeating those questions.

Skills check for this file at `.agents/product-marketing-context.md` (or `.claude/product-marketing-context.md` for older setups).

### Skill Interdependencies

Skills cross-reference each other by name. Key routing relationships:
- **`page-cro`** → for full pages; routes signup flows to `signup-flow-cro`, post-signup to `onboarding-cro`, standalone forms to `form-cro`, popups to `popup-cro`
- **`ab-test-setup`** → for experiment design; routes copy creation to `copywriting`
- **`product-marketing-context`** → should always run first on a new project

### Evals

Each `evals/evals.json` contains scenario-based tests. To run evals for a skill, use your preferred eval runner against the prompts and assertions in that file. Assertions are plain-English checks on agent output — they are not code assertions.
